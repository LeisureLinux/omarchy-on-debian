# 把 Omarchy 4 的桌面搬进 Debian 13：一次完整移植复盘，以及「没有最大化按钮」之后

> 一台 H3C 笔记本，一块 2.5K 屏，Debian 13 + Hyprland。
> 我想用 Omarchy 4（Quattro）的那套桌面——顶栏、菜单、通知、主题、天气一整套。
> 它是 Arch Linux 发行版的一部分。于是有了这次移植。

---

## 一、Omarchy 是什么

Omarchy 是一个基于 Arch 的发行版，真正让人一眼记住的是它的**桌面外壳（shell）**。

这套外壳的技术栈很干净：

| 组件 | 角色 |
|---|---|
| **Quickshell** | 用 QML 写桌面 UI 的运行器，进程名叫 `qs`（不是 quickshell，别被名字骗了） |
| **Hyprland** | Wayland 合成器 + 平铺窗口管理器 |
| **`omarchy-*` 脚本** | 90 多个 bash 脚本，QML 通过 `execDetached` 调用它们干活 |
| **主题系统** | `themes/` + `shell.toml` 模板渲染，换主题是换一整套配色与背景 |

关键在于：**这套外壳只有 2 MB 左右的 QML/JS**，本身不挑发行版。它挑的是周围那一圈——Arch 的会话管理器、包集合、图标字体，以及 Qt 版本的一两个脾气。

移植的本质，就是把这一圈补齐。

---

## 二、最大的不同：Wayland，不是 X11

这是 Omarchy 与传统桌面（Windows / macOS / 大部分 Linux 桌面）**最根本的分野**，比平铺不平铺更重要。

传统 X11 的模型是：一个叫 X Server 的中枢进程，所有窗口都挂在它上面，任何客户端都能问它「现在屏幕上都有什么」「把鼠标移到哪」「那个窗口里现在显示啥」。这套设计诞生于 1984 年，**安全模型基本等于没有**——任意一个前台应用都能截屏、监听全局键盘、读取别的窗口内容。

Wayland 换了个模型：

```
X11:   应用 → X Server → 合成器 → 屏幕        （中枢可窥探一切）

Wayland: 应用 → 合成器（Hyprland）→ 屏幕      （客户端彼此隔离）
```

在 Wayland 下，**合成器就是显示服务器**。Hyprland 既负责合成画面，也负责窗口管理。应用之间互相看不见；一个应用想截屏、录屏、取色，必须走 `xdg-desktop-portal` 的授权流程，用户点头才行。全局热键、全局输入法、剪贴板，全都有各自的 Wayland 协议，不再是「谁都能读」的全局状态。

带来的直接后果是**工具链全线换血**：

| 你在 X11 用惯的 | Wayland 上的替代品 |
|---|---|
| `scrot` / `import` 截图 | `grim` + `slurp`（选区） |
| `xclip` / `xdotool` | `wl-clipboard` / `wtype` |
| 全局取色器 | `hyprpicker` |
| `xrandr` 管显示器 | `hyprctl monitors` |
| `xbacklight` 调亮度 | `brightnessctl` |

X11 老应用还能跑，靠的是 **Xwayland** 兼容层——一个跑在 Wayland 里的 X Server。但兼容层里跑的应用就退回了 X11 的安全模型：它们能互相窥探，而且**它们窗口上的最小化、最大化按钮，大概率是失效的**。这一点后面还会讲。

顺带说一句常被误解的事：Wayland 不是「Linux 的某种桌面」，它只是一套协议。GNOME、KDE、sway、Hyprland 都实现它，但各自的观感可以天差地别。Omarchy 选的是 Hyprland 这一支。

## 三、理念冲突：最小化按钮为什么点了没反应

装机之后最容易被问到的一个问题是：

> 「Chrome 右上角的最小化按钮，点了怎么没反应？」

**这不是 bug，是理念不同。** 而且这个按钮在 Wayland + 平铺管理器下，本来就没有意义。

### 传统桌面的世界观：窗口是可以自由摆放的纸

Windows 和 macOS 的基本假设是：屏幕是一张桌子，窗口是一张张纸，你随手摆。摆乱了怎么办？于是需要三个按钮：

- **最大化**：把这张纸临时铺满桌子
- **最小化**：把纸暂时收起来，去翻别的
- **关闭**：把纸扔掉

这三个按钮存在的**前提**，是「窗口位置由用户手动管理、且可以重叠」。

### 平铺窗口管理器的世界观：位置是计算出来的，不是摆出来的

Hyprland 反过来：**窗口自动铺满，布局由管理器计算**。开第二个窗口，屏幕自动二分；开第三个，继续切分。你不需要、也没机会把窗口摆在「差不多那个位置」。

于是那三个按钮失去了存在的基础：

- **最大化** = 这个工作区只放一个窗口。平铺管理器的默认状态就是这样，不需要按钮。真要「独占屏幕」，快捷键 `Super+F`（fullscreen）比按钮更快。
- **最小化** = 「把这个窗口挪走，但别关掉」。平铺管理器里，每个工作区的窗口是平铺好的，没有「收起来」这个中间态——一个窗口要么在这个工作区占一格，要么不在。

Hyprland 0.55 的实测结果很能说明问题：

```bash
hyprctl dispatch minimize
# Invalid dispatcher
```

**根本不存在 minimize 这个动作。** 所以 X11 应用（Chrome、Electron 系）通过 Xwayland 发出的「请最小化我」请求，到了合成器这层没有对应实现，点了就是静默无响应。按钮还在，因为在 X11 的协议里它应该在那儿；但没人接它。

我的处理方式——把「最小化」这个概念翻译成平铺管理器听得懂的话：

```ini
# 把窗口挪到一个专门存放的隐藏工作区
bind = $mainMod, M, movetoworkspacesilent, special:minimized
# 需要时再把它调回来
bind = $mainMod, R, togglespecialworkspace, minimized
```

效果上等价于最小化/还原，而且是**真的**等价：窗口状态保留、不占当前工作区的平铺位置、随时召回。

### 思维转换才是重点

从传统桌面过来，真正要换的不是快捷键，是**管理对象**：

| 传统桌面 | 平铺 + Wayland |
|---|---|
| 管理**窗口**（摆位置、叠层次） | 管理**工作区**（哪个应用去哪块地） |
| 鼠标找窗口 | 键盘切工作区（`Super+1..9`） |
| 最小化 = 收起来 | 挪到别的工作区 |
| 最大化 = 铺满 | 单窗口工作区 / fullscreen |
| 开始菜单点应用 | 启动器（`Super+D`） |

适应之后最大的感受是：**手不用离开键盘，脑子里也不用维护「我刚才把那个窗口放哪了」这张地图**。工作区是稳定的，窗口是流动的。

至于 X11 应用上那些失效的按钮——它们就像电动汽车上留着的加油口盖，位置还在，功能已经不需要了。

## 四、移植实战：六个步骤

整套流程我做成了可重放的脚本，仓库在文末。核心六步：

**1. 依赖**
Quickshell 和 Hyprland 0.55 不在 Debian 13 稳定源里，需要 `trixie-backports`，并把优先级钉在 100——只补缺口，绝不顺手升级稳定包。Nerd Font Debian 不提供，脚本检测到缺失会自动下载。

**2. 取源码**
`omacom/omarchy` 的 `quattro` 分支，浅克隆即可。

**3. 部署**
把 `shell/ bin/ config/ default/ themes/` 同步到 `~/.local/share/omarchy`，再装启动器。

**4. 打补丁**
四个补丁（下面讲）。

**5. 字体**
两件事：装 Omarchy 专用图标字体；强制 `monospace` 指向 Nerd Font。

**6. Hyprland 绑定**
autostart、启动器键、最小化模拟工作区。

每一步都能单独重跑（`./install.sh --only 40`），改文件前自动备份，最后有 `70-verify.sh` 打健康表。

## 五、五个必踩的坑（都是静默失败）

移植过程中真正耗时的不是写代码，是**五处不报错的静默失败**。

**① Qt 6.8 的保留字**
通知插件里有个变量叫 `transient`，在 Qt 6.8 的 QML 里是保留字，整个通知系统崩掉。改名 `isTransient` 解决。

**② 菜单项全部哑火，一条错误都没有**
菜单动作走 `bash -lc`（login shell），`/etc/profile` 会把 PATH 重置，导致 90 多个 `omarchy-*` 脚本全部 `command not found`——在后台静默地。修法是把 PATH 写进 `~/.profile`。
排查口诀：**用 `bash -lc 'command -v omarchy-menu'` 复现，而不是在交互式终端里试。**

**③ `uwsm-app` 不存在**
上游把所有应用启动都包了一层 `uwsm-app`（Arch 的 Wayland 会话管理器）。Debian 没有，结果每个菜单项都是空操作。写了个 shim：`exec "$@"`。

**④ 顶栏日期整块消失**
`Qt.formatDate(date, fmt, locale)`——这个 Qt 版本从 QML JS 里既不接受 locale 名字字符串，也不接受 `QLocale` 对象，直接抛异常。**QML 绑定表达式抛异常的表现是渲染成空白，没有任何弹窗**。改成两参调用，月份名自己在 JS 里本地化。

**⑤ 天气图标全是豆腐块**
`fc-match monospace` 在中文 locale 下解析到了某个宣称支持 200+ 语言的 CJK 字体，它没有 Nerd Font 的私有区字形。普通的 `<alias><prefer>` 压不住它，必须用 `binding="strong"` 的强前缀。

这五条的共同点：**都不弹错误框**。所以移植这一类东西，第一件事是把 `qs` 的 stdout 抓到文件里，然后 grep。

## 六、一个彩蛋：中文农历时钟

既然都改了，索性给日历加上农历。

节气不能靠公式估算，用**寿星天文历（sxtwl）**生成 1900–2099 逐年的节气表；农历大小月与闰月用 `lunardate` 的表。两张表都是脚本生成、可校验的，不是手打的。

显示优先级：**节日 > 节气 > 农历日**。初一显示月份名（「七月」），闰月加「闰」字。顶栏展开后大标题是「丙午年七月廿四」这种完整写法。

写的时候踩了个典型的 off-by-one：QML 侧的月份是 **0 基**（9 月传 8），而表是按 **1 基**生成的。没统一之前，白露会显示成前一个月的节气。

## 七、值不值得

折腾下来我的判断：

**值得的部分**——Wayland 带来的安全模型（应用之间真的看不见了）、平铺之后手不离键盘的效率、以及一个完全由文本配置、可版本化、可重放的桌面环境。整套桌面我可以用一个 `install.sh` 在另一台机器上重建出来，这在 Windows 或 macOS 上不可想象。

**要付的代价**——X11 应用会带进来一批半失效的交互习惯（最小/最大化按钮就是典型）；某些周边功能（远程桌面、部分屏幕共享）在 Wayland 下仍需额外配置；以及你需要接受「配置即代码」这件事，好处是可复现，代价是上手要读文档。

如果你已经在用 Debian + Hyprland，想试试这套桌面，仓库在这里：

**https://github.com/LeisureLinux/omarchy-on-debian**

```bash
git clone https://github.com/LeisureLinux/omarchy-on-debian
cd omarchy-on-debian
./install.sh --dry-run     # 先看一遍会做什么
./install.sh               # 再执行
./steps/70-verify.sh       # 随时体检
```

脚本是幂等的，重复执行安全；改任何文件前会备份；上游更新后 `--only 40` 可以只重新打补丁。
