# Rust crates → .deb packaging

For Rust applications that Debian trixie main / contrib does **not**
ship but your desktop actually wants (e.g. `wpaperd`, `swww`,
`waypaper`, `mako`, `wlr-which-key`, ...).

## Why not `cargo install --root /usr/local`?

It works for a single machine but produces no audit trail, no
version pin, no dependency declaration, and no apt hook. We want
apt-trackable packages so that `omarchy-update-orphan-pkgs` and
`apt-mark showmanual` treat them like every other system package.

## Strategy

```
crates.io ──cargo──▶ target/release/wpaperd  (statically strippable)
                       │
                       ▼  fpm -s dir -t deb
                     *.deb
                       │
                       ├──▶  local install (sudo dpkg -i)
                       │
                       └──▶  repo.freelamp.com  (PUSH=1 reprepro)
```

## Usage

For an existing crate (template assumes `wpaperd` as example):

```bash
cd packaging/wpaperd
CRATE=wpaperd VERSION=1.0.1 \
  CRATE_BIN=wpaperd \
  DESCRIPTION="Wayland wallpaper daemon with timed rotation" \
  DEPS='libwayland-client0,libwayland-cursor0,libdbus-1-3' \
  bash ../rust-crate-deb/build.sh
```

The script:
1. `git clone` the upstream tag (v$VERSION) into `build/src/`
2. `cargo build --release --locked` (proxy env stripped — wpad.lan
   cannot reach crates.io)
3. `strip --strip-unneeded` the binary
4. Stages `usr/bin/<bin>` plus any `EXTRA_FILES` into `build/stage/`
5. `fpm -s dir -t deb` produces
   `packaging/<crate>/build/<crate>_<version>_amd64.deb`

To upload to **repo.freelamp.com**:

```bash
PUSH=1 bash ../rust-crate-deb/build.sh
```

(requires `reprepro -b /srv/freelamp` to be set up on the build host;
out of scope for this repo — see `docs/freelamp-reprepro.md` if you
later publish it.)

## Conventions

| Path in stage             | Purpose                                   |
|---------------------------|-------------------------------------------|
| `usr/bin/<bin>`           | main binary, mode 0755                    |
| `usr/bin/<extra>`         | additional bins from `EXTRA_BINS`         |
| `usr/share/<pkg>/...`     | static assets, example configs            |
| `usr/lib/systemd/user/`   | systemd user units                        |
| `DEBIAN/control`          | generated by fpm from env vars            |
| `DEBIAN/{post,pre}{inst,rm}` | generated by fpm only when files exist  |

## Why not `cargo deb`?

`cargo deb` is the obvious choice but it embeds a `debian/` directory
in every crate, doesn't handle multi-binary crates well, and adds
another moving part. We only need a thin shell over `fpm` — the fpm
template lives in this repo, so it survives upgrades.
